# SNS Video Factory — MVP実装計画（正本）

**更新:** 2026-11-17  
**最優先:** コードと計画の整理 → **既存MulmoCastを動かす最小実証** → 無料接続 → Web化。別の動画制作基盤は開発しない。

## 決めた仕様

- 自然な文章で企画し、必要ならChatGPT等の成果を**そのままコピペ**。内蔵LLMも使えるようにする。
- **MulmoScript v1.1を唯一の脚本正本**とし、会話履歴等は必要なときだけ最小限追加。別のStoryboard型を必須にしない。
- ユーザーが「生成開始」したら、既存の`audio → images（画像生成＋画像→動画）→ captions → avatar → movie`を**連続実行**。カットごとの承認はしない。
- I2Vで実際に動画を生成する。静止画のズームだけで動画生成を代用しない。
- 無料APIを利用してよいが、**有料・料金不明のAPIへ一切自動フォールバックしない**。実行前に全経路を検査し、無料Tier不足・未承認の利用規約では停止する。
- 初期から大規模なDB、独自ジョブエンジン、独自AIエンジン、独自編集エンジンは作らない。
- 将来の共有Webにはログイン・永続ストレージ・APIキーの保護が必要。**完成したことにしない**。

### 2. 無料のAI接続と安全ガード（段階実装）

**最初の安全PR（PR #12）:** 本番の無料生成元がまだ承認されていないため、まず`movie --sns-free-only`を追加。ローカル素材と既存mockのみ許可し、意図しない有料画像/動画/TTS/翻訳などの経路を事前拒否する。既存のオフライン連続動画テストを同モードで通す。GroqのFree Planを明示確認した場合にのみ、既存GraphAIへ`openai/gpt-oss-20b`を渡す企画生成入口も追加（実APIはキーがなく未検証）。[無料モードの詳細](./FREE_TIER_SAFETY.md)

**画像AI実績（PR #13）:** Cloudflare Workers FreeのFLUX.1 Schnellを既存画像Agentに接続。[実際のCloudflare APIを使用した手動試験](https://github.com/ToramaruA/sns-video-factory/actions/runs/44014541975)で**静止画1枚→2秒・720×1280のMP4**に成功（2026-11-17）。ここでは画像を動かすI2Vは実行していない。

**GroqとFLUXの連結（PR #15、実API成功）:** すでに単独成功したGroqの3カット企画を、既存のFLUX画像AgentとMulmoCast `movie --sns-free-only` に渡し、無音・静止画3カット・6秒の縦型MP4を作る**手動限定**の経路を追加。企画原本の `moviePrompt` は保持し、別の安全なプレビュー用MulmoScriptを構築する。Groq FreeとWorkers Freeの双方を実行前に利用者が確認した場合にのみ実API呼び出し可能。CIではオフラインテストだけを行う。**3枚の実画像生成と6秒MP4は[2026-11-17の手動実行](https://github.com/ToramaruA/sns-video-factory/actions/runs/44066142099)で成功。実動画I2V・音声・Web化は未完成。** [連結実験の詳細](../../experiments/07-groq-flux-three-cut/README.md)。

**次の実動画の実証（PR #16、手動実験の準備）:** PR #15で生成したGroq企画とFLUX画像3枚を再利用し、既存のWan 2.2実験Agentで**1カットだけ2秒I2V**にし、残り2枚の静止画と既存MulmoCastで6秒MP4へ結合する。Groq/FLUXの再生成なし。Spaceへの匿名デモ送信には明示的な2条件確認が必要で、CIでは外部I2Vを実行しない。Wan/ZeroGPUは商用共有サービスの供給源として未承認であり、通常の無料モードへ加えない。[実験手順](../../experiments/08-one-cut-wan/README.md)。**2026-11-17の手動実行で、Wanによる2秒動画1本＋静止画2枚の縦型6秒MP4生成に成功**（[実行記録](https://github.com/ToramaruA/sns-video-factory/actions/runs/44102870424)）。3カット全動画化と継続無料運用は未実証。

**縦型の中身を画面全体に表示（PR #18、検証中）:** 当初は720×1280のMP4に対してMulmoCast既定の`aspectFit`が適用されており、正方形・横型の生成画像の上下に黒余白が入る場合があった。MulmoCast標準の`movieParams.fillOption.style: "aspectFill"`を、静止画プレビュー・1カットWan実験・混合MP4・ローカル音声付きMP4の全経路に指定して中央切り抜きで画面を満たす。Square入力からの縦型出力は黒帯検出付きオフラインE2Eで検証する。**Cloudflare FLUX.1 Schnellの公式入力スキーマはprompt/stepsだけでwidth/height指定に非対応**。これはネイティブな9:16画像生成ではなく、左右の切り落としが起きるため、AIのプロンプトで中心55%に重要被写体を収める。被写体保護の完全保証はまだできず、将来は商用利用可・継続無料が確認された縦型ネイティブモデルの接続を優先検討する。元MulmoCastのcrop/scale実装を再利用し、新しい動画エンジンは作らない。外部APIはテストで実行しない。

**ローカル音声結合のオフライン実証（PR #17、検証中）:** 既存MulmoCastの `beat.audio`、音声結合、FFmpegを流用し、1カットの動画＋2枚の静止画＋3カットごとの音声ファイルから音声付きMP4を生成する。外部TTSは一切呼ばず、無音でない音声トラックを検証。音声はテスト信号であり、**台本の日本語を実際に読み上げたわけではない**。その後、継続無料で利用条件を満たす日本語TTSを調査・接続する。リップシンクは後回し。[オフライン手順](../../experiments/09-local-narration-e2e/README.md)。

**次の企画AI段階（PR #14）:** Groq Free Planの`gpt-oss-20b`を使った既存GraphAIの3カット・縦型MulmoScript企画生成を、**手動で明示実行**できるようにする。テストはモックで通し、実APIテストはGroqのFree契約とキーが登録されてから。[手動企画生成の説明](./GROQ_FREE_PLANNING.md)。**企画を作るだけ**で、この段階で画像やI2Vは実行しない。

## PRのルール

- 本体機能との重複を**実装前に確認**。必要性が説明できない独自コードは追加しない。
- 外部APIの実験は、無料Tier・規約・実施回数・失敗時の挙動を記録し、課金しない設定でのみ実行。
- CIの外部課金API呼び出しは禁止。成功テストと実生成の確認結果は明確に区別する。
- 課金、素材や個人情報の権限、本番の外部生成先に不確実性があれば**止める**。
