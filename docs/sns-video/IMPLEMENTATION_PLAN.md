# SNS動画ツール — 開発方針（正本）

更新日: 2026-11-18  
ブランチ: `restart/mulmocast-upstream-free-ai`  
**目的: MulmoCastをそのまま利用し、利用料金が発生するAIの部分だけを、条件を満たす無料AIへ置き換える。**

この文書は新ブランチの実装判断の基準である。旧mainの `docs/sns-video/IMPLEMENTATION_PLAN.md` を含む従来の独自MVP計画より、このブランチでは本方針を優先する。

## 1. 絶対に守る原則

1. **MulmoCastの機能を削らない。** 企画・カット割り、MulmoScript（JSON/YAML）、画像・動画・音声入力、参照画像、各beat設定、生成、字幕、編集可能な構造、最終動画結合など、公式の既存機能を維持する。無料AI側がサポートしない機能があっても、MulmoScriptのフィールドを勝手に捨てたり、無言で静止画に置き換えたりしない。
2. **最初に既存のprovider/model/API設定で代替可能か調べる。** 置換設定だけで済むものはコードを書かない。既存プロバイダーが使えない場合のみ、MulmoCastの既存エージェント/プロバイダー接続の規約に従って最小限のアダプターを追加する。
3. **新しい動画制作基盤を作らない。** 独自のカット割りエンジン、別Storyboardスキーマ、専用編集エンジン、独自ワークフロー、モデル切替UI、大規模な認証/DB/ジョブ基盤を増やさない。
4. **コストについて曖昧なままAPIを呼ばない。** APIキーの存在だけでは無料と判断しない。利用するアカウントのFree Tier、API経由の課金条件、利用上限、商用/SNS宣伝利用・共同利用の条件を確認する。未確認・有料・条件外なら実行前に停止し、有料への自動フォールバックは禁止する。
5. **無理な代替で品質を落とさない。** 例えば動画生成用に指定された `moviePrompt` を捨て、静止画MP4にして「AI動画化成功」とは扱わない。実I2Vの無料提供元が確認できない場合は「未対応・保留」と明示する。
6. **既存MulmoCast本体に対する変更を最小化する。** 変更前に元の実装を読み、追加・修正の理由と、対応した既存機能への影響を記録する。生成・編集・出力の既存APIと形式の後方互換を保つ。
7. **小規模・少人数利用を想定。** GUIが本当に必要になったときだけMulmoCast公式の既存UI/beat-editorを評価し、独自の機能制限付きWebアプリを先に作らない。

## 2. 入力と処理の範囲（元のMulmoCastから変えない）

### 企画から開始する経路

自然文での対話入力、ローカルテキストファイル、URL由来のテキストなど、既存 `mulmo tool scripting` 系の入力経路を維持する。

**既存LLMに代わる無料LLM**が、元のテンプレートとMulmoScriptスキーマを使って構成・カット割り（複数 `beats`）を生成する。LLMによる企画生成を独自実装しない。

### 完成済みの台本から開始する経路

**MulmoScript（JSON/YAML）をそのまま入力**する。カット構成を再生成しない。画像のローカルパス/URL/参照画像、既存音声・動画、beatごとの画像/動画プロンプト等の指定を元の意味どおりに処理する。

画像だけを渡して自動で構成を作る機能は、標準 `scripting` の確認済み入力とは異なるため、**この再出発の必須範囲に勝手に追加しない**。必要になればMulmoCastの既存機能と最小追加の要否を別途検証する。

### 生成・出力

元のMulmoCastの **`mulmo movie <script>`** を中心に、音声・画像（必要に応じて画像→動画）・字幕・動画結合の既存処理を再利用する。最終出力は従来どおりMP4等。参照画像は対応モデルでは画像データを直接渡す。非対応モデルでは機能を削除せず、代替の選定か明示的な停止を選ぶ。

## 3. 変更対象はAI接続に限定する

| 工程 | 基本の扱い | 必要な確認 |
| --- | --- | --- |
| 企画・カット割りLLM | 元MulmoCastの `tool scripting` と既存Groq等のLLMプロバイダー設定を使う | 実際のモデルとAPI無料条件、スキーマ品質 |
| 画像生成 | MulmoCast既存image agent/providerの設定を優先 | 参照画像、素材入力、画像品質、Free Tier |
| 動画生成（I2V/T2V） | MulmoCast既存movie agent/providerの設定を優先 | 画像入力・実動画出力、無課金条件、商用・共同利用 |
| ナレーション/TTS | MulmoCast既存TTS設定を優先し、必要時だけローカル等の無料音声アダプター | 日本語音質、表記義務、API料金 |
| 字幕・編集・結合 | **原則変更しない** | 回帰テストのみ |

「無料」とは**アカウント・利用方法・上限・規約が確認でき、想定利用時に請求が発生しないこと**を意味する。無料トライアル残高、実質有料のAPI、ブラウザのみ無料でAPI有料の提供元は、確認なしには採用しない。無料枠超過時は生成前にブロック、または提供元の明示的な無料枠エラーで停止する。無制限無料は約束しない。

## 4. 実装順序・完了条件

1. **元MulmoCast単体の動作確認**: 既存CLI、MulmoScript入力、画像/音声/動画素材の指定、MP4作成の基本経路を確認。既存コードの振る舞いを記録する。
2. **AI接続一覧の監査**: LLM / image / movie / TTS の既存プロバイダー・モデル・料金・権利・無料枠・参照画像対応を表に整理。既存設定だけでできる変更を先に実施。
3. **最小限の無料化**: 本体のprovider/agent境界だけに必要な変更を入れる。既存のユーザー入力やMulmoScriptスキーマは変更しない。
4. **回帰テスト**: 元のMulmoCastと同じ台本を使い、無料化で画像参照、動画入力、台本生成、TTS、字幕、MP4結合が不必要に失われないことを確認。無料経路のオフライン検証と、ユーザーが事前確認した無料アカウントによる実API検証を区別する。
5. **完成判定**: 使用する無料AIが必要な動作を満たし、料金条件・必要な権利を確認でき、実際の動画が作れること。I2Vの無料経路が見つからない場合、**未完成部分として明記**し、静止画をAI動画化と称さない。

## 5. 既存の作業の扱いとGit履歴

- 旧mainは**保存したまま**で、新ブランチを公式 `receptron/mulmocast-cli` のコミット `c410d188536cfe4150a12c47c2a767525b9100ed` から開始した。旧mainをリセット・削除・強制プッシュしない。
- 旧mainにある独自ブラウザ入口、独自Groq企画経路、静止画専用MulmoScript変換、独自テスト群は**新ブランチへ無条件に移植しない**。
- 過去に調べた無料モデルやAPIの情報だけを、必要時に**現行条件を再確認した上で**再利用する。
- 作業ごとに「元MulmoCastのどの既存処理を再利用し、どのAIを変更したか」「既存機能を制限したか」「無料条件の根拠」をPR・コミットに記載する。

## 6. 途中で誤った方向へ進まないためのレビュー条件

実装前に必ず確認する:

- これは**MulmoCast既存機能で解決できるか**？
- AIの**提供元・モデル・設定の変更だけ**でできない理由は何か？
- 既存の**MulmoScript入力、参照画像、素材、音声、動画出力**を壊していないか？
- 無料AIで不可能な箇所を黙って削除・代替していないか？
- API利用が無料であることと、SNS宣伝等で利用できることを確認したか？

いずれかが未確認なら機能追加を急がず、具体的な未確認事項を記録する。

## 7. 進捗と今後の実装順序（2026-11-19、実動作確認に基づく）

- この2工程は**別のGitHub Actions実行**であり、現在のワークフローは固定サンプルと既存artifactのrun IDに依存する。「任意の企画から一発生成」「任意のMulmoScriptをそのまま一発生成」はまだ実装・実証していない。
- Groq Freeによる既存 `mulmo tool scripting` の新ブランチ実API確認、生成された台本に適切な `imagePrompt` / `moviePrompt` が入るか、ユーザー自身の台本編集からの一括実行も未検証。
- 現行Wanは**匿名ZeroGPUデモ**、1カット2秒・明示同意あり・最大3リクエスト/プロセスという実験枠。継続無料・宣伝用途・他者への提供における許可と安定性は未承認。商用利用可能な本番プロバイダーとは呼ばない。

- 参考画像の品質・人物同一性、映像全体の一貫性、リップシンクは未検証または後回し。

### 次に進める優先順位

**P0 — 1本のMulmoScriptから、音声・画像・I2V・字幕・MP4を一括生成できるようにする。**

**実装状況（2026-11-19）:** 同じMulmoScriptにFLUX画像3枚、Wan動画3本、日本語Gemini TTS、字幕の設定を保持する `docs/sns-video/examples/experimental-three-cut-onepass-narrated.json` を追加。Wan実験の最大3回・明示同意とGemini無料枠確認をそれぞれ維持し、`mulmo movie <script>` 1回で処理できるよう無料モードの事前ガードを変更。GitHub Actions `onepass_narrated` を追加（初期選択）。ビルド・型チェック・単体/回帰テスト・LintはCI [44333422547](https://github.com/ToramaruA/sns-video-factory/actions/runs/44333422547) で成功。**実API生成はGitHub Actions [44338853334](https://github.com/ToramaruA/sns-video-factory/actions/runs/44338853334) で成功しP0完了**。1回の `mulmo movie` でGemini日本語TTS 3本→Cloudflare画像3枚→Wan動画3本→MulmoCast字幕→音声付き720×1280/30fps MP4（6.006秒）まで実行し、artifact保存も成功。次はP1のGroq無料LLMによる企画からMulmoScript生成・既存movie経路接続。


1. いまは無料ガードが「Wanで動画を生成するbeatでは `suppressSpeech: true` が必須」としており、同一MulmoScriptの同一実行でGemini TTSとWanを同時使用できない。無料枠の事前チェックを維持したままこの制限を解く。
2. 固定サンプル名や過去のartifact run IDを入力前提とせず、**MulmoScriptのパス指定**で既存MulmoCast CLI `movie` を動かす最小の実行方法を整える。動画の参照画像/素材・beat単位の指示を壊さず、勝手な静止画への変更をしない。
3. **日本語音声＋動画を同時に作る3カットMulmoScript**を実APIで検証する。期待する画面数、各カットの実動画、音声、字幕、720×1280 MP4の有無を検証し、無料枠・実験同意の確認は最初に行う。ここが「最小の一括動作確認」の完了基準。

**P1 — ユーザー入力を完成したMulmoScriptに接続する。**

**実装状況（2026-11-19）:** 元MulmoCastの `tool scripting --input-file --template sns_free_vertical --llm groq --llm_model openai/gpt-oss-20b` を利用する。SNS縦型動画用の元MulmoScript形式のテンプレートを `assets/templates/sns_free_vertical.json` と `scripts/templates/sns_free_vertical_video.json` に追加。既存GitHub Actions `sns-video-groq-flux-three-cut-manual.yml` の再出発ブランチ版に企画文入力、Groq Free Plan確認、生成MulmoScriptのアーカイブと無料安全チェック、任意の一括 `mulmo movie` を接続。**Groq実APIでの企画生成は[GitHub Actions #44350517524](https://github.com/ToramaruA/sns-video-factory/actions/runs/44350517524)で成功（3カット、MulmoScript安全検証・成果物保存まで通過）。** さらに**[GitHub Actions #44351718878](https://github.com/ToramaruA/sns-video-factory/actions/runs/44351718878)で企画文→Groq台本→3カットCloudflare画像→Wan I2V→Gemini日本語音声→MulmoCast字幕付きMP4を1回の実API実行で成功**。生成動画は720×1280・30fps・約6.1秒（H.264/AAC）、3本のMOVと字幕画像・完成MP4のartifactも保存。固定サンプルに依存しない企画入力経路の実証完了。ただし編集済みの任意MulmoScript入力、参考画像、カット数可変、商用・継続無料運用条件は別途検証が必要。独自LLMエージェントは追加していない。


4. 企画文 → 既存 `mulmo tool scripting --llm groq --llm_model openai/gpt-oss-20b` → MulmoScriptを実際の無料アカウントで確認。画像指示・動画指示・適切なcut数を満たさなければ、**既存のテンプレート／プロンプト**を最小変更して補う（独自カット割りエンジンは禁止）。
5. 完成済みMulmoScript入力の場合はLLMを通さず編集済み台本を直接実行。MulmoCast既存の画像・動画・音声・参照画像入力を保持する。編集はまず既存のJSON/YAMLと公式編集機能で行い、新規UIは作らない。
6. 企画からの1本と、完成済み台本からの1本を実際に生成できれば「小規模向けMVP」と判定する。

**P2 — 作品としての最低限の破綻を修正する。**

7. Wanの実クリップ長、各beatの画面表示時間、Gemini TTSの発話長を数値で比較し、末尾停止・不自然な尺のズレを直す。既存MulmoCastの尺・速度・編集機能を先に調べ、新しい結合機能を自作しない。
8. プロンプト品質・連続カットの世界観・参考画像（人物同一性）・画像比率・日本語発話と字幕の可読性を段階的に改善。個別カット再生成と既存キャッシュを確認する。
9. 演出・BGM・効果音の追加は既存のMulmoScript機能で必要に応じて行う。リップシンクは後回し。

**P3 — 無料運用の成立条件を確定する。**

10. Groq / Cloudflare / Gemini の各アカウントFree Tier、リクエスト上限、課金防止、SNS宣伝利用可否を再確認。特にWanの第三者ZeroGPU公開デモは運用上の最大の未確定要素として代替可能な無料I2Vプロバイダーを調査する。十分な条件を満たす候補がなければ試作品と明記し、無理に本番公開しない。
11. 複数モデル切替は信頼できる別プロバイダーが実際に見つかった時だけ既存provider境界に追加する。無料枠切れは停止、課金モデルへ自動フォールバックしない。

### 今は作らないもの

独自ブラウザ制作UI、独自storyboard/編集エンジン、データベース・ログイン・ジョブキュー、モデル自動選択エージェント、リップシンク、大規模品質評価システム。公式MulmoCastの既存機能で本当に足りないと分かるまで増やさない。

### 完了の定義

- 企画文または完成済みMulmoScriptを指定でき、途中で台本/beatを編集可能。
- 動画化指定したbeatは**実際の動画**として生成し、静止画を無断で代用しない。
- 画像/既存素材/参考画像・日本語TTS・字幕・動画結合が一つのMulmoCast制作経路で動作する。
- Free Tierと用途の条件が確認され、想定外の有料APIを事前に拒否する。
- 少なくとも2種類の入力経路で実動画を生成・確認し、失敗時はどの工程か分かる。
