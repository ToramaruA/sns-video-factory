# 実装計画・判定基準・未決事項

**状態:** 2026-11-15時点の計画。検証結果に応じて更新する。  
**狙い:** 既存MulmoCastを再利用しつつ、継続無料のAI・承認・共同利用を無理なく実現する。

## 実装前の再利用監査（2026-11-15更新）

既存機能と独自追加の境界を [REUSE_AUDIT_2026-11-15.md](./REUSE_AUDIT_2026-11-15.md) に整理した。**GraphAIはフォークに組み込み済みでコピー不要**。元MulmoCastの対話LLM、文章→MulmoScript変換、動画・画像生成、キャッシュ、字幕/音声、FFmpeg編集を再利用する。

**新しい確定方針:** 継続無料のAPIは許可する。APIキーの利用者個別設定は必須にせず、運営側の**課金が起きない無料Tier**から明示的に選ぶ。無料APIが限界なら停止・待機し、有料APIへ切り替えない。ChatGPT等の外部AIで作った企画は、特殊な書き出し形式を使わず**普通の文章をチャット欄に貼り付ける**。

**重要な見直し:** PR #8の独自StoryboardをMulmoScriptと二重の脚本正本として拡大しない。MulmoScriptを唯一の脚本正本とし、会話・revision・無料枠・ジョブの最小状態のみ追加する。**初期版はユーザーが企画を確認して「生成開始」した後、既存MulmoCastで画像→動画→編集を連続実行。画像/動画ごとの承認・再生成は後回し**。PR #7の承認コードは残すが現時点では未接続とする。

## 1. 決定・仮決定・保留を分ける

| 状態 | 項目 | 理由 |
|---|---|---|
| **要求として確定** | AIが企画・演出・カット割りを提案 | SNS動画制作を簡単にするため |
| **要求として確定** | 各カットの静止画を作り、それぞれ画像→動画AIで動画化 | 「静止画のズームだけ」を代替策にしない |
| **要求として確定** | 企画を会話で修正し、生成開始は利用者が操作 | 画像・動画の個別承認は将来の任意拡張 |
| **要求として確定** | 生成先を複数用意し、手動選択・条件付き自動切替 | 一社の枠・停止・品質に依存しない |
| **要求として確定** | 継続無料を優先、意図しない課金なし | 無料APIは利用可。期間限定の体験枠だけでは不足 |
| **要求として確定** | 内蔵LLMと外部AIの企画文ペーストを併用 | API契約不要で普段のChatGPT等を活用できる |
| **要求として確定** | 共有Webツール、利用人数に固定上限を置かない | 利用人数ではなく無料生成枠が実際の制約 |
| **実装方針として採用** | MulmoCastフォークを基盤として再利用 | 動画生成・結合・字幕などの既存実装がある |
| **実装方針として採用** | MulmoScriptを脚本の正本とし、実行履歴を分離 | 既存DSL互換性と連続実行を優先 |
| **暫定** | クラウド上のフロントエンド + API + DB + ストレージ + ワーカー | 複数利用者・非同期ジョブに適している |
| **保留** | 無料動画AIの実サービス・方式 | 自動利用、商用利用、無料枠、成功率の実証が未完了 |
| **保留** | Cloudflare / GitHub Actions / その他の本番実行基盤 | コスト・実行上限を実測して選ぶ |
| **保留** | 認証方法（個人ログイン、組織招待、共通メール等） | セキュリティ・運用コストを比較する |
| **保留** | 参考動画を動作条件に使う際の共通DSL表現 | 対応モデル次第。既存MP4読込と区別する |

## 3. 最初の開発PRの作り方

1. `main`で直接実験しない。機能ごとに短いブランチを作る。
2. 実装PRには目的、前提、テスト結果、無料/有料APIの呼び出し有無、失敗時挙動を書く。
3. 生成AIの検証PRは、実際に得たサンプルMP4や結果ログを記録する。ただし個人素材・秘密鍵をコミットしない。
4. 有料API利用可能性が増える差分は、**明示的に課金停止条件のテストを追加**。
5. 成功条件を満たしたPRから順番にマージする。CIが失敗・未完了なら調べる。

## 5. 設計を見直す判断基準

- **無料生成AIが実証できない:** できたふりをしない。別プロバイダー、規約に合うGPU環境、低解像度、段階実装を再検討する。
- **既存MulmoCast内部の改造が増えすぎる:** 必要な接続部分だけ分離し、元コードの更新取り込みが可能な構成を見直す。
- **生成の待機時間が長すぎる:** UIに待機の理由と回復の不確実性を示し、ユーザーが企画の見直しなど別作業をできるようにする。
- **参考動画がAI条件付けできない:** 「参考としてアップロード可能」と「動作転写可能」を明確に分けて表示する。
- **無料の実行枠が本番負荷に耐えない:** 料金を伴う方法へ無断で変更せず、運用制限・待機方針を見直す。
