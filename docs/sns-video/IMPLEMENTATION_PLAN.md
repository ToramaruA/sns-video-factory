# 実装計画・判定基準・未決事項

**状態:** 2026-11-15時点の計画。検証結果に応じて更新する。  
**狙い:** 既存MulmoCastを再利用しつつ、継続無料のAI・承認・共同利用を無理なく実現する。

## 1. 決定・仮決定・保留を分ける

| 状態 | 項目 | 理由 |
|---|---|---|
| **要求として確定** | AIが企画・演出・カット割りを提案 | SNS動画制作を簡単にするため |
| **要求として確定** | 各カットの静止画を作り、それぞれ画像→動画AIで動画化 | 「静止画のズームだけ」を代替策にしない |
| **要求として確定** | 人間が適切な段階で承認・修正 | 品質保証と意図の反映 |
| **要求として確定** | 生成先を複数用意し、手動選択・条件付き自動切替 | 一社の枠・停止・品質に依存しない |
| **要求として確定** | 継続無料を優先、意図しない課金なし | 期間限定の体験枠だけでは不足 |
| **要求として確定** | 共有Webツール、利用人数に固定上限を置かない | 利用人数ではなく無料生成枠が実際の制約 |
| **実装方針として採用** | MulmoCastフォークを基盤として再利用 | 動画生成・結合・字幕などの既存実装がある |
| **実装方針として採用** | MulmoScriptと実行状態・承認履歴を分離 | 既存DSL互換性とカット単位の再実行 |
| **暫定** | クラウド上のフロントエンド + API + DB + ストレージ + ワーカー | 複数利用者・非同期ジョブに適している |
| **保留** | 無料動画AIの実サービス・方式 | 自動利用、商用利用、無料枠、成功率の実証が未完了 |
| **保留** | Cloudflare / GitHub Actions / その他の本番実行基盤 | コスト・実行上限を実測して選ぶ |
| **保留** | 認証方法（個人ログイン、組織招待、共通メール等） | セキュリティ・運用コストを比較する |
| **保留** | 参考動画を動作条件に使う際の共通DSL表現 | 対応モデル次第。既存MP4読込と区別する |

## 2. 段階的に実装する

### Phase 0 — MulmoCastを壊さず基礎確認（現在）

- [x] フォークを作成
- [x] `src/actions/images.ts`、`src/agents/`、`src/actions/movie.ts`、MulmoScript v1.1の主要仕様を確認
- [x] PR [#1](https://github.com/ToramaruA/sns-video-factory/pull/1) にローカルMP4×2本をMulmoCastで結合するテストを追加
- [x] PR #1の**専用Actionsが成功**。6秒、720x1280、シーンの違いをチェック
- [x] PR #1のNode.js CIも成功を確認し、**2026-11-15にmainへマージ**
- [ ] 元MulmoCastのCI全体の負荷を把握し、不要な大量実行を避ける案を検討

**達成基準:** 元のエンジンでMP4結合が無料・再現可能に動くこと。※画像→動画AIを検証したことにはならない。

### Phase 1 — 継続無料の画像→動画AIを1つ実証（最優先の難所）

**初回成果（2026-11-15）:** [Wan2.2/ZeroGPUの匿名API呼び出しで画像1枚から2.0625秒のMP4を実生成](./PROVIDER_RESEARCH_2026-11-15.md)。ただし本番サービスへの導入・安定提供・共同利用時の規約は引き続き未検証。

1. 候補ごとに利用規約、商用/宣伝利用、継続無料枠、合法な自動利用方法を確認。
2. 画像1枚 + 動きの文章から、実際に短いMP4を生成。
3. 可能なら開始フレーム一致、9:16、尺、出力解像度、失敗率を確認。
4. 生成AIの失敗が料金や権利の問題か、技術的問題かを分類。
5. 実際に使える候補だけを採用。対応するアダプターを`src/agents/`に追加。
6. MulmoScript→元のカット処理→新アダプター→生成MP4まで通す。

**合格条件:** 一時的な無料トライアルではなく、継続無料で許可された経路を使って、MulmoCastの1カットからMP4を生成できること。**未達なら無料動画生成が可能と宣伝しない。**

**追試成果（2026-11-15）:** Wan 2.2生成MP4をアーティファクトから取得し、**MulmoCastで別カットと結合して4.07秒の縦型MP4を出力するテストも成功**（[run 43623282651](https://github.com/ToramaruA/sns-video-factory/actions/runs/43623282651)）。ただし専用の生成Agentを経由した一工程の自動生成は未完了。無料枠と利用規約の本番適合性検証も必要。

### Phase 2 — 無料AI接続の抽象化と自動切替

- [ ] 少なくとも2つの異なる生成経路をアダプターで用意
- [ ] モデルごとに入力機能（i2v、比率、長さ、参照画像等）を機械可読で定義
- [ ] 無料枠・利用不可・手動停止を扱うルーター
- [ ] 自動切替時に必須の入力条件を省略しない
- [ ] 生成ID・同じジョブの重複実行防止・再試行回数上限
- [ ] **有料APIが選択されない**ことを確認する負のテスト

**合格条件:** 1つ目が利用できなくても、互換性があり無料利用可能な2つ目へ切替可能。条件に合う提供元がなければ安全に停止する。

### Phase 3 — AIディレクターと絵コンテ・画像承認

- [ ] 依頼から目的、ターゲット、動画尺、演出、各カットを構成
- [ ] 縦型SNSフォーマットに適したMulmoScriptを作成・スキーマ検証
- [ ] 企画を複数案提示し、人が修正・承認
- [ ] 参考写真・ロゴ・動画の参照関係を記録
- [ ] 各カットで静止画生成、プレビュー、承認・差し戻し
- [ ] 同一人物や商品などの画像の一貫性を保つ改善ループ
- [ ] 動画生成前に**承認された画像**を使う検査

**合格条件:** 企画や1カットのみ修正しても、承認済みの無関係な画像・動画は消えない。

### Phase 4 — 個別動画レビューから最終編集まで

**合格条件:** 一部のカットを再生成しても、最終編集工程で生成AIが勝手に再実行されない。

## 3. 最初の開発PRの作り方

1. `main`で直接実験しない。機能ごとに短いブランチを作る。
2. 実装PRには目的、前提、テスト結果、無料/有料APIの呼び出し有無、失敗時挙動を書く。
3. 生成AIの検証PRは、実際に得たサンプルMP4や結果ログを記録する。ただし個人素材・秘密鍵をコミットしない。
4. 有料API利用可能性が増える差分は、**明示的に課金停止条件のテストを追加**。
5. 成功条件を満たしたPRから順番にマージする。CIが失敗・未完了なら調べる。

## 4. 次に調査する項目

### 最優先

- 自動利用が公式に許可される**継続無料の画像→動画**の実行先
- 画像を入力に使う機能、必要尺（数秒で十分か）、9:16、ロゴ・人物の再現性
- 実生成試験と無料枠回復条件、宣伝用途の許可

### その後

- 無料画像生成先と無料LLM（AIディレクター）
- 参照写真と参考動画をどう渡すか（原本動画の編集 vs AIに動作を条件付け）
- Web・DB・ストレージ・動画ワーカーの無料枠・ジョブ実行方式
- チーム認証・招待・権限とデータ削除方針

## 5. 設計を見直す判断基準

- **無料生成AIが実証できない:** できたふりをしない。別プロバイダー、規約に合うGPU環境、低解像度、段階実装を再検討する。
- **既存MulmoCast内部の改造が増えすぎる:** 必要な接続部分だけ分離し、元コードの更新取り込みが可能な構成を見直す。
- **生成の待機時間が長すぎる:** UIに待機の理由と回復の不確実性を示し、企画や画像承認など別作業を先に進める。
- **参考動画がAI条件付けできない:** 「参考としてアップロード可能」と「動作転写可能」を明確に分けて表示する。
- **無料の実行枠が本番負荷に耐えない:** 料金を伴う方法へ無断で変更せず、運用制限・待機方針を見直す。
